# Agent qualification evidence → Model Artifact Foundry: public projection contract

Status: **PROPOSED, unmerged. No model has been qualified by this document.**
Date: 2026-11-17

## Purpose

Real project development and model/agent qualifications may uncover reusable facts about a third-party *model artifact*, its provenance, representation or runtime compatibility. This Foundry receives **only the public-safe artifact-specific projection**. It does not own hosted API model evaluations, generic coding-agent rankings, task dispatch, task package registries, or the private planner.

Authoritative related work:
- [Model Spelunker #198](https://github.com/SemperSupra/model-spelunker/issues/198): real-work AGY/Gemini work-sample qualification and public-safe configured-actor receipts, following #139 and #105.
- [Agent Dispatch private #104](https://github.com/SemperSupra/agent-dispatch-private/issues/104): configured-actor qualification and routing authority.
- [Agent Dispatch private #830](https://github.com/SemperSupra/agent-dispatch-private/issues/830): free-tier data-disclosure admission.
- [Model Artifact Foundry Private #37](https://github.com/SemperSupra/model-artifact-foundry-private/issues/37): private exact-target fit, private evidence, model selection and promotion controls.

## Separation of concerns

| Fact or output | Authoritative destination |
| --- | --- |
| Real product implementation, tests, acceptance | Owning product issue and PR |
| Exact configured actor, harness, model/API, task outcome, verifier and uncertainty (approved public-safe subset) | Model Spelunker |
| Portable artifact identity, public upstream revision/license, representation format, generic validated compatibility | Model Artifact Foundry |
| Private target mapping, unpublished measurements, internal selection/routing and private model-evaluation corpus | Model Artifact Foundry Private |
| Actor placement, delegated authority and API-data admission policy | Agent Dispatch Private |

Hosted Gemini API model IDs, API credentials or free-tier entitlement observations are **not** by themselves OCI artifact identities, approvals, or redistributable model weights. Nothing in this interface adds a general-purpose LLM evaluation warehouse.

## Admission and projection requirements

1. Pre-admit the complete free-tier *payload*, not just its repository name: user prompt, source/context, tool responses, retrieved documents, agent follow-up inputs and media. Approval must be explicit, reviewable and source-bound; missing or UNKNOWN = DENY. An agent with unrestricted filesystem/tool access is **not** isolated by a manifest preflight alone.
2. Public projection may contain only rights-cleared public source/fixture references, safe reproducible test/validator contracts, source/revision/digest identifiers, and provenance-backed *artifact-specific* compatibility evidence.
3. Do not copy private test result corpora, private workstation inventory, credentials, rejected internal candidates, consumer mapping, strategically revealing scoring, or unpublished rights/compatibility observations to this repository.
4. Discovery, candidate creation, validation, promotion and consumer digest selection remain distinct Foundry states. A model doing well as a coding assistant never approves any weight/OCI artifact. Metadata or hashes prove identity, not quality, rights or safety.
5. New artifact metadata or validator changes require a concrete reusable artifact/consumer use case, existing Foundry schema compatibility, deterministic positive+negative verification and human review. If the source work yielded only actor-performance evidence, **NO FOUNDRY ARTIFACT CHANGE REQUIRED** is the correct result.
6. No model-byte harvesting, gated terms acceptance, publication, review bypass, new credential authority, or paid service activation follows from this document.

## Incremental real-project qualification sequence

A. Qualify the existing local Windows AGY launcher and external free-tier admission against a deliberately original public fixture; capture the configuration/harness evidence in Spelunker. This does **not** entail changing a Foundry model.

B. Work through genuinely open, nonoverlapping issues prioritized in Spelunker #198: public synthetic MMD serializer/geometry failure, original Go DSP numerical/scene integration, dataset source-lineage/rights validation, and operational freshness/receipt telemetry, followed by camera/visual critics when rights and execution are admitted.

C. Each project receives a bounded, independently reviewed patch/falsification. Spelunker receives task+actor evidence and task-conditioned uncertainty. Foundry Private receives selected confidential applicability/rejection evidence. This public Foundry receives an update **only where an independently useful, portable third-party artifact/representation/license/provenance/compatibility result exists.** Otherwise record the reason in the private planning DLE.

D. For genuinely reusable artifact discoveries, first inspect current Foundry issue/PR and existing schemas; draft a minimal public-safe addition and negative controls. Do not silently advance approved digests.

## Receipt handoff minimum

A Spelunker-to-Foundry artifact-specific proposal, **not automatically a committed record**, must carry:
- originating product issue/PR and independently verified outcome reference;
- public task/fixture digest and rights approval;
- pinned upstream model-artifact identifier/revision, *if a real artifact exists*;
- representation/runtime version and exact identity kind (OCI digest vs local content-manifest as applicable);
- precise claim type (metadata, analytic estimate, equivalent-target measurement, exact-target measurement, project quality);
- verifier/version/negative controls and PASS/FAIL/UNKNOWN;
- explicitly approved public fields and separate private evidence locator;
- status PROPOSED until accepted under existing Foundry governance.

## Success/stop

Success means the work contributes verified improvements to real project repositories and creates reusable, correctly scoped evidence without compromising the public/private boundary. Stop or HOLD on unclear rights, unseen private data, unknown artifact identity, unsupported API tier, source revision drift, quota exhaustion, disputed owner authority, or an unverified result. No self-merge, release or publication.

This is a documentation-only interface proposal. No runs have been executed or accepted under this new campaign as of its creation.
